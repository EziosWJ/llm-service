# 领域文档

工程技能在探索代码库时如何消费本仓库的领域文档。

## 探索前先读这些

- 仓库根目录的 **`CONTEXT.md`**，或
- 仓库根目录的 **`CONTEXT-MAP.md`**（如果存在）——它指向每个上下文的 `CONTEXT.md`，按主题读取相关文件。
- **`docs/adr/`** —— 读取与当前工作领域相关的 ADR。在多上下文仓库中，还需检查 `src/<context>/docs/adr/` 中的上下文级决策。

如果这些文件不存在，**静默跳过**。不要提示缺失，也不要主动建议创建。生产者技能（`/grill-with-docs`）会在术语或决策确定时按需创建。

## 文件结构

单上下文仓库：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-event-sourced-orders.md
│   └── 0002-postgres-for-write-model.md
└── src/
```

## 使用术语表中的词汇

当输出中涉及领域概念时（问题标题、重构提案、假设、测试名称），使用 `CONTEXT.md` 中定义的术语。不要偏离术语表明确避免的同义词。

如果所需概念尚未收录，这是一个信号——要么你在发明项目不使用的语言（需重新考虑），要么确实存在空白（记录下来供 `/grill-with-docs` 处理）。

## 标记 ADR 冲突

如果输出与现有 ADR 矛盾，应显式提出而非静默覆盖：

> _与 ADR-0007（事件溯源订单）矛盾——但值得重新讨论，因为……_
